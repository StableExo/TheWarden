# M0 - Measurement harness (spec v0.6)

Author: Claude (eesel). Date: 2026-11-26. Read-only prep; nothing has been run.

## Purpose

Produce the first honest numbers: over a fixed window, what opportunities the system sees on Base, and what net P&L each one implies after fees, slippage and gas. No trade is broadcast. This is the artifact the whole program rests on.

## Revision v0.2 - Copilot's audit (2026-11-27)

Full detail in `AUDIT.md`. Copilot's key finding: the default entry can boot and reach live pool discovery, but it is **not measurement-grade**, and parts of the detection path are **stubs that fabricate opportunities** (`src/services/scanner.ts`, `src/services/pathfinding.ts`), while `ProfitabilityCalculator` hardcodes $3000/ETH and may double-count costs.

**Revised M0 approach:** do not instrument the existing path, and do not use `recordSimulationResult` as the record source (it stores only route, gas estimate, wouldSucceed, error). Instead write a **purpose-built read-only snapshot script** built on `DEXRegistry` + `MultiHopDataFetcher` + `AdvancedOrchestrator`, forcing live data, narrowed to WETH/USDC on two or three venues, emitting one JSONL record per candidate path plus a summary.

## What the entry points actually are (audit result)

- `npm run start` = `node --import tsx src/main.ts`. This is what `start-base-warden.sh` runs (it sets `DRY_RUN` and calls `npm run start`).
- **`src/main.ts` is heavily stripped:** dozens of imports are commented out with a `[DEAD]` marker (AdvancedOrchestrator, IntegratedArbitrageOrchestrator, ArbitrageOrchestrator, GasPriceOracle, SensoryMemory, PerceptionStream, DashboardServer and more). So "one polished system" overstates it; the entry point is mid-refactor.
- **The documented strategy runner is broken:** `examples/arbitrage/base_weth_usdc_runner.ts` imports `src/services/BaseArbitrageRunner`, which does not exist (404). That example cannot run as written.
- **The governance chokepoint is real:** `src/execution/GovernedExecution.ts` routes every opportunity through Supabase as a single chokepoint - it enqueues in `execution_queue`, logs a `proposed_trade` in `cognitive_ledger`, and reads permission from `guardrail_policies`. It is fail-safe by design: if Supabase is unreachable or no policy applies, the decision is dry-run and never broadcasts. It also exposes `recordSimulationResult` for DRY_RUN telemetry, and an idempotency key from chain/pair/pool/block.

## Step 0 - prove the components, then build the snapshot (rewritten v0.5)

The forbidden hooks are gone: do not use `GovernedExecution` or `recordSimulationResult`, and do not instrument the scanner or pathfinding stubs. Step 0 is:

1. **Prove the three named components are real**, not dead imports or stubs: `DEXRegistry`, `MultiHopDataFetcher`, `AdvancedOrchestrator`. Note `AdvancedOrchestrator` is commented out with a `[DEAD]` marker in `src/main.ts`, so confirm it is importable and runnable directly.
2. **Pin the run parameters in writing** before running: the 2-3 venues, the `amountIn` test size, the block window length, and whether Supabase is configured (M0 does not require it).
3. **Build the purpose-built read-only snapshot** on those three components, forcing live data, emitting records to `base-debt/artifacts/`.
4. If a component turns out to be a stub or unimportable, that is itself the M0 result: the repair becomes the milestone.


## Pre-register before running (Sonnet, 2026-11-27)

Two parameters must be fixed in writing **before** the run, so the result cannot be fitted to it:

- The **bps tolerance** that defines "reconciles" (how close the model must come to the on-chain Quoter for a record to count).
- The **block range** and **how it was chosen**, so the window cannot be cherry-picked after the fact.

## Additions v0.4 - Gemini's guardrails (2026-11-27)

- **Do not let `ProfitabilityCalculator` emit a single net figure.** Log, as separate fields: the raw quoted output; exact gas units; the live ETH/USDC spot read from the WETH/USDC pools in the same block; the Aave premium read on-chain (`FLASHLOAN_PREMIUM_TOTAL`, expected 0.05%); and the simulated execution output from an `eth_call` / Quoter static call rather than the V3 reserve approximation. A single blended net lets its hardcoded constants hide inside the answer.
- **Parallel latency data, deferred decision (Sonnet):** collect p50/p95 round-trip to the sequencer from the current box while M0 runs, but do not act on it until parity passes.
- **Venue parity fallback (Sonnet):** if V3 or Aerodrome cannot reach parity within tolerance, evaluate those venues Quoter-only rather than stalling.
- **No `debug_`/`trace_` dependency.** Public Base endpoints do not serve those namespaces, so M0 must not use them.
- **Poll cadence (to pin):** one snapshot per block over the pinned range (proposal: 600 blocks, ~20 min at 2s), recording calls-per-snapshot so the cost can be forecast.
- **Pin each snapshot to one `blockTag`.** Querying several venues across a multi-hop path without a pinned block drifts across blocks, which looks identical to phantom arbitrage. Repeat the snapshot at many pinned blocks to get persistence (with Sonnet's block range).

## Additions v0.3 - Sonnet's review (2026-11-27)

- **Pin to blocks, run over a range.** Every record carries a block number, and M0 runs over a block range, so the snapshot shows persistence, not a single moment.
- **Reconcile against the chain.** Replace the approximate V3 reserve math with on-chain **Quoter** calls at the pinned block, and log the model-vs-quoter gap in bps. That reconciliation is what makes M0 measurement-grade rather than model output.
- **Read costs on-chain, not from constants.** Aave's `FLASHLOAN_PREMIUM_TOTAL()` (this settles the 0.09% vs 0.05% discrepancy), each pool's fee, and Base's L1 data fee on top of L2 gas. Convert gas to USDC at the pool's mid price at that block, which retires the hardcoded $3000/ETH.
- **Write the pass/kill rule before running.** M0 succeeds if the output reproduces and reconciles, not if it finds profit. WETH/USDC is heavily contested, so expect most candidates to be net-negative. And state in the summary header that a snapshot cannot show capturability (latency, competition) - it measures what was visible, not what was winnable.

## What to log (one record per opportunity seen)

- `ts`, `chainId`, `blockNumber`
- `pair` (e.g. WETH/USDC), `route` (venues + fee tiers in order), `hops`
- `amountIn` (test size), `grossSpreadPct`, `feeCostPct`, `slippagePctEst`, `gasCostEstUsd`, `netProfitPct`, `netProfitUsd`
- `wouldRevert` (from the simulation), `revertReason` if so
- `decision` (dry-run / require-approval / deny), `reason`
- `missReason` when net is not positive: no-spread / fees-ate-it / slippage / too-slow / reverted

Write to `base-debt/artifacts/opportunities-<window>.jsonl` plus a one-page summary.

## The summary report (the deliverable)

- Window start/end, blocks covered, opportunities seen per hour.
- Net-positive count and the distribution of net (median, p90, max, negative tail).
- The reason breakdown for misses.
- Cost model stated explicitly (fee tiers, gas estimate, slippage assumption) so a reader can check it.
- One sentence on what the numbers mean, including if the answer is "there is no edge at this size."

## Pass criteria

The report exists, its arithmetic reconciles (sum of components equals net for each record), and it was produced against live Base pool data, not a fixture. A negative result passes too; an unreadable or unreconciled one does not.

## Needs from the human lead

- `BASE_RPC_URL` for Base mainnet (read-only is enough for M0).
- A decision: use Supabase (enables the governance chokepoint and its telemetry) or run the fallback local-file instrumentation.
- No wallet key or funds are needed for M0; nothing is broadcast.

## Risks

- The path may not run at all, in which case M0's output is that finding plus a repair list, and the repair becomes the milestone.
- Supabase may not be reachable from the runner's environment; hence the fallback.
- A thin opportunity set at our size would be a real, publishable result, not a failure of the harness.
